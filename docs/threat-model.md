# Production Threat Model — Digital Impersonation Response Desk

## Purpose and Scope

This document defines the production threat model for the **Digital Impersonation Response Desk** in accordance with Node 2 of the Phase 9 architecture. The scope encompasses the multi-tenant SaaS application, SQLite database engine, local and managed object storage, background worker processes, external read-only integrations (YouTube Data API v3 & WebSub), and administrative control surfaces.

| **T-08** | WebSub Webhook Endpoint | **Malicious Provider Webhook** | Attacker sends forged YouTube Atom feed notifications to inject fraudulent monitoring signals. | HMAC-SHA1 signature verification (`X-Hub-Signature`) using per-subscription shared secret. | Request timestamp replay window checks, source IP filtering against Google IP ranges. | High | Constant-time HMAC comparison (`crypto.timingSafeEqual`), emergency kill switch suspension. | `phase8-security-audit.test.ts` |

| **T-10** | Tenant Data Boundary | **Tenant Breakout Attempt** | Malicious tenant crafts malicious SQL fragments or URL parameters to jump tenant boundaries. | Parameterized queries with `better-sqlite3`, Zod schema validation on all inputs. | Static analysis SAST rules enforcing tenant scoping on all prepared statements. | Critical | Strict schema parsing, rejection of unsanitized SQL identifiers, tenant middleware assertion. | `independent-verification.test.ts` |
| **T-11** | SQLite Database | **Database File Compromise** | Unauthorized process or operator accesses raw `.sqlite` file on host storage. | Write-Ahead Logging (WAL) mode, foreign key enforcement, restricted file permissions (0600). | Full-disk encryption (LUKS / BitLocker), SQLite encryption extension (SQLCipher / SEE). | High | Host OS file permissions, isolated container mounts, non-root container execution. | `production-hardening.test.ts` |
| **T-12** | Object Storage Bucket | **Object-Storage Compromise** | Misconfigured cloud storage bucket exposes stored evidence files publicly. | Opaque UUID keys, segregation from web root, signed URLs with short expiration (300s). | Bucket policy blocking all public access, SSE-KMS encryption with customer-managed keys. | Critical | `ManagedObjectStorage` abstraction enforcing private ACLs, SSE-KMS headers, and pre-signed tokens. | `managed-storage.test.ts` |
| **T-13** | Operational Logs | **Log Leakage (PII / Secrets)** | Application logs inadvertently output OAuth tokens, passwords, encryption keys, or sensitive evidence. | Custom structured logger with JSON output, explicit omission of token fields in route responses. | Centralized automated PII and credential redacting filter in logger transport pipeline. | High | Automated redaction regex masks passwords, tokens, auth tags, and IVs before log emission. | `production-hardening.test.ts` |
| **T-14** | Background Workers | **Worker Compromise / Loop Hijack** | Malicious task payload causes infinite retry loop, worker starvation, or memory exhaustion. | Worker heartbeats in `worker_heartbeats`, scheduled interval timeouts. | Bounded retry limits, exponential backoff, dead-letter state tracking, graceful shutdown handlers. | High | Max 5 retries with dead-letter queueing, SIGTERM/SIGINT graceful shutdown handlers. | `failure-injection.test.ts` |
| **T-15** | Software Supply Chain | **Dependency / Supply-Chain Attack** | Malicious update introduced into upstream npm package dependency. | `package-lock.json` committed, explicit version pinning. | Automated `npm audit` in CI, Dependabot / Renovate scanning, lockfile hash verification. | High | Regular vulnerability scans, verification of package integrity, rejection of suspicious postinstall scripts. | `dependency-audit.md` |
| **T-16** | Infrastructure Network | **Denial of Service (DoS)** | Volumetric HTTP flood or resource-intensive regex query overwhelms single-threaded Node.js event loop. | Express body parser size limits, busy timeout on SQLite (5000ms). | Reverse proxy rate limiting (Nginx / Cloudflare), clustering, circuit breakers. | High | Application-level rate limiters on auth, sync, and webhooks; request size ceilings (1MB API, 10MB XML). | `production-hardening.test.ts` |
| **T-17** | Human Operator | **Accidental Operator Action** | System operator accidentally deletes production database or triggers bulk takedown. | Zero live platform takedowns (`ENABLE_LIVE_PLATFORM_ACTIONS = false`), dual-control deletion. | Administrative action confirmation modals, destructive command blocks in scripts. | Critical | Fail-closed configuration, read-only provider adapters, anti-overwrite backup restore guards. | `production-hardening.test.ts` |
| **T-18** | Backup Archive | **Backup Compromise / Tampering** | Backup archive is tampered with or modified to inject malicious evidence or corrupted schemas. | SHA-256 database and file checksums recorded in `backup-manifest.json`. | Backup encryption at rest with separate backup key, GPG signature on manifest. | High | Cryptographic verification of manifest hashes prior to allowing restore; rejection on hash mismatch. | `failure-injection.test.ts` |
| **T-19** | Disaster Recovery Target | **Restoration into Wrong Environment** | Operator accidentally restores backup directly over active production database directory. | `restoreToIsolatedTarget` checks target path against active DB path and throws error. | Mandatory `--force-production-restore` flag requiring explicit two-person confirmation. | Critical | Hardcoded invariant in `BackupService` rejecting any restore where target directory matches runtime DB. | `failure-injection.test.ts` |
